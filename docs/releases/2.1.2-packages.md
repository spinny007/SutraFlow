Version 2.1.2, 289 files each (the Administration Guide and its pictures are new). 2.1.2 changes no database tables and no settings; it upgrades from 2.1.0 and 2.1.1.

## What changed since 2.1.1

- A new SutraFlow Administration Guide (`/admin-guide`) with the administration chapters of the user guide and the former `docs/deployment.md`, and new pictures of the installer, the upgrade pages and the Admin Console.
- The user guide, for designers, in parts and in reading order, with the connection pictures beside their palettes.
- The web installer saves its answers as a config file without passwords, and writes and offers its log.
- Safer upgrades: the engine beside the studio stops and starts with it, program files are checked before anything moves, the way back restores only what an upgrade changes and always starts the old version, and an SQLite file of its own is upgraded as SQLite.

## Release gates

**Done on 27 October 2026:**

- **Full test suite** on real PostgreSQL 18 (pgvector) and MySQL (Laragon): 540 tests, 529 passed, 0 failed, 11 skipped. The skipped tests need outside services: real brokers, MongoDB Atlas, Docker, and a remote database with TLS.
- **Installer tests**: 12 passed, including the new ones:
  - saved answers keep every choice, write each password as an environment variable, and validate as an install once those are set;
  - an upgrade asks the launcher to stop both the studio and the engine beside it, and knows whether the engine ran;
  - an SQLite file of its own is SQLite; a file held without sharing by another process (Windows) stops the upgrade before anything changes, naming that process, and the old version starts again; read-only Git objects in the data folder are left alone.
- **A real upgrade of Laragon 4810 from 2.1.0 to 2.1.2** through the web installer's upgrade pages, with a PowerShell window still open in its `bin` folder:
  - the first attempt (before the fixes) failed and its way back stopped on a read-only Git object, leaving it stopped; the data folder was then compared with a backup taken before and was unchanged, and 4810 was started again on 2.1.0;
  - with the fixes, `bin` was copied into the backup and updated in place, every other folder moved, the database dumped and checked (51 tables), and 4810 answered 2.1.2 on PostgreSQL. Backup: `C:\laragon\www\sutra\backups\2.1.0-202610271018`.
- **Administration Guide pictures** taken by `tools/capture-admin-shots.mjs` on a throwaway installation from the offline archive (PostgreSQL in a temporary database, removed afterwards): every installer page, the Admin Console, and the upgrade pages. The progress picture comes from an upgrade of that throwaway installation, marked 2.1.1; the other upgrade pictures from the real 4810 upgrade.
- **User guide pictures** refreshed on 4800 with `npm run guide:shots`.
- **Both guides served**: `/guide`, `/admin-guide` and their file names answer; links between them open the other guide at the chapter.
- **Web installer from the offline archive**, driven through its API in a fresh folder: version 2.1.2 shown; no log before anything ran; the answers file holds no password and keeps the choices; an SQLite install completed every step; the log downloads as a file, holds the steps and the result but no password, and is written to `data/logs/installer.log`.
- **Silent install from the saved answers** in a second fresh folder: `install --config sutraflow-install.json --dry-run` accepted the file and printed the plan.
- **Connections in the browser** (from 2.1.1, same code): HTTP, PostgreSQL local and remote, MySQL local and remote, Kafka, RabbitMQ, ActiveMQ and MongoDB Atlas, each tested and saved.
