## Gates

- **Tests**: full suite, 641 test cases (614 tests by the README badge count), with local PostgreSQL and MySQL on Laragon: 627 passed, 10 skipped (real brokers, Atlas, remote databases and Docker not configured here), 4 failed. All four were fixed and run again:
  - `test/api-docs.test.ts`: the two new routes were described while the suite was already running (passes 4/4);
  - the README badge, raised from 578 to 614 (regression and the PGlite PostgreSQL suite then 31/31);
  - `test/contract217.test.ts`: the test counted the called Sutra's runs before the run started without *Wait* had written its child; it now waits for that child first (8/8, three times).
- **New tests**:
  - `test/paths217.test.ts`: the lane rule in the designer, the design check and the engine;
  - `test/connections217.test.ts`: line colours, the palette contrast, Tidy, and room for lines in every sample;
  - `test/contract217.test.ts`: Manual start with an XSD, the Call Sutra contract, refusal before the child starts;
  - `test/stage217.test.ts`: run stages, filters, the batched fill and design-run retention, on SQLite and PostgreSQL;
  - `test/fixes217.test.ts`: the page link and the missing sample data hint.

  The observability test checks the new `stage` label on the run metrics.
- **Screenshots**: every user guide picture was retaken on the 2.1.7 studio, plus 10 new ones (lines and colours, Path, Trigger data, the colour key, reference origins, the step menu, the Call Sutra contract, the page link, the Runs stage filter). The Administration Guide pictures were retaken on a throwaway installation of the offline package (installer, Admin Console, and an upgrade to 2.1.7 of that installation); its folder was emptied afterwards.
- **Outside services** (the skipped tests, run afterwards with the connections notes kept outside the repository):
  - local RabbitMQ 4.4: 9/9;
  - local ActiveMQ 6.3 (AMQP 1.0 and OpenWire): 15/15;
  - remote PostgreSQL and MySQL over TLS: 3/3;
  - broker REST: 3/3 run, all passed (RabbitMQ management, ActiveMQ Jolokia, the generated REST samples). The first run failed the two RabbitMQ parts: the local RabbitMQ had no plugins ("0 plugins started", AMQP on 5672 only). After `rabbitmq_management` was enabled they passed. Kafka REST stayed skipped: there is no Kafka REST address.
  - Kafka: 0/9, because the hosted Kafka trial has ended and its broker name no longer resolves (`ENOTFOUND`). It needs a new Kafka service before it can run again.
  - MongoDB Atlas: not run. The credentials on hand were exposed earlier and are not used until replaced.
- **Image**: `sutraflow image build` from the source folder gave `sutraflow:2.1.7`, 610 MB. In a container:
  - studio mode: `/health` answered 2.1.7, it runs as `node`, and the four guides are in `/app/docs`;
  - engine mode: healthy, and `sutra status` inside the container (with `SUTRA_ADMIN_TOKEN` set) reported ready with no address or token typed.

  `docker stop` exited 0 both times. The image-build test in `test/docker.test.ts` skips on Windows by design; the Linux release job builds it.
- **Not done**:
  - **24-hour remote-PostgreSQL soak.** This is the backlog's only Must have and the release gate, and it is **deferred again** (decided 7 November 2026). 2.1.7 changes the designer and the bookkeeping of runs: the path rule, run stages and retention. It does not change how engines share work, take claims or recover. The new column and the batched fill are covered on SQLite and PostgreSQL by the tests. The item stays the Must have in the backlog.
  - Kubernetes and the cluster from the image were not run again; their files changed only in the version.
- **Release workflow**: not yet run (the tag is pushed by the maintainer).
